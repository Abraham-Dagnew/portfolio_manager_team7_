# Portfolio Manager

A full-stack portfolio management application built as a training project. It lets a single user track a financial portfolio of stocks, ETFs, bonds, and cash - buying and selling against a real cash balance, and viewing live performance backed by real market data from Yahoo Finance.

## Features

- **Browse holdings & transaction history** - a tabbed view: **Holdings** shows one aggregated position per ticker (net quantity, average cost basis), **Transactions** shows the raw buy/sell history. Search by ticker filters either tab.
- **Buy assets** - search for a real stock, ETF, or bond by ticker or company name, auto-fill the live market price, and purchase it. A "Popular Right Now" widget on the Buy page surfaces real trending tickers (live price + daily % change) for one-click buying. Purchases are validated (ticker format, positive quantity/price, real purchase date) and rejected if they'd exceed the available cash balance.
- **Sell holdings** - sell shares of any holding at the live market price directly from the Holdings table; there's no delete - selling is how a position is reduced, so the transaction history stays a true record instead of something that can be rewritten.
- **Cash balance tracking** - a single running cash balance funds every purchase. Funds can be deposited or withdrawn freely (withdrawals can't take the balance below $0), and the balance updates live as holdings are bought or sold. Selling credits the cash balance at the current market value.
- **Portfolio performance dashboard** - live total value, total cost, realized P/L, unrealized P/L, total P/L, and % return, computed against real-time prices. Realized P/L is locked-in profit/loss from past sells (tracked per ticker even after a position is fully closed), unrealized P/L is the paper gain/loss on shares still held, and total P/L combines both. Includes a gain/loss chart per holding and an asset allocation chart showing portfolio composition.
- **Live market data** - ticker validation, price lookups, search, and trending tickers are all backed by real Yahoo Finance data via `yfinance`, not mocked/static data.
- **Retry-safe purchases** - buy, sell, deposit, and withdraw requests support an `Idempotency-Key` header, so a request that never received a response (e.g. a dropped connection) can be safely retried without double-executing.
- **Interactive API docs** - full Swagger/OpenAPI documentation auto-generated by FastAPI.

## How to Use

1. **Browse Holdings** (`/portfolio`) - shows everything currently held, aggregated per ticker, with a **Transactions** tab for the raw buy/sell history. Ticker search filters either tab, and a position can be sold directly from the Holdings table.
2. **Buy** (`/add`) - an asset can be found by ticker or company name, either through search or by selecting one from the "Popular Right Now" panel; its type and live price auto-fill once selected. After entering a quantity, the purchase is rejected with a clear message if the ticker isn't valid or if it would exceed the available cash balance.
3. **Performance** (`/performance`) - shows how the portfolio is doing: summary cards for total value, total cost, realized P/L, unrealized P/L, total P/L, and unrealized gain %, a gain/loss chart, an asset allocation chart, and a detailed per-holding table - all using live prices. Realized P/L still shows even for positions that have been fully sold off.
4. **Cash Balance** (sidebar, always visible) - displays the current balance, with `+`/`-` controls to deposit or withdraw funds at any time.

## Technologies Used

**Backend**
- [Python](https://www.python.org/) / [FastAPI](https://fastapi.tiangolo.com/) - REST API framework
- [Pydantic](https://docs.pydantic.dev/) - request validation (tickers, positive numbers, enums, dates)
- [MySQL](https://www.mysql.com/) (`mysql-connector-python`) - persistent storage for holdings and cash balance
- [yfinance](https://pypi.org/project/yfinance/) - live market data (prices, search) from Yahoo Finance
- [Uvicorn](https://www.uvicorn.org/) - ASGI server

**Frontend**
- [Flask](https://flask.palletsprojects.com/) - serves the HTML pages
- Vanilla JavaScript (ES modules) - API calls, form validation, live UI updates, no framework/build step
- [Chart.js](https://www.chartjs.org/) - gain/loss and asset allocation charts
- Hand-written CSS - sidebar/dashboard layout, toast notifications, responsive design

**Testing**
- Python `unittest` - unit, integration, and performance/benchmark tests (`backend/tests/`)
- Node's built-in test runner (`node:test`) - frontend API-client tests (`frontend/tests/`)
- Playwright + pytest - end-to-end tests that drive the real UI in a browser against both live servers (`backend/tests/e2e/`)
- GitHub Actions - the unit/integration/performance and frontend suites run automatically on every push and pull request (`.github/workflows/tests.yml`). The e2e suite isn't wired into CI yet - it requires both servers running live, so for now it's run manually.

## Project Structure

The backend follows a Web → Service → Persistence layering:

```
backend/
  main.py                  Web layer: FastAPI routes, request schemas, HTTP error translation
  services.py              Service layer: business rules (balance checks, share checks, cost-basis aggregation)
  persistence.py           Persistence layer: raw SQL only, no business logic
  idempotency.py           Retry-safety wrapper used by the web layer around mutating service calls
  errors.py                Domain error types shared by the service and web layers
  db_conn.py               MySQL connection + table setup/migrations
  math_logic.py             Pure performance/gain calculation functions
  yahoo_service.py         Live price lookup, search, and trending tickers via yfinance
  requirements.txt          Backend dependencies
  .env / .env.example       MySQL credentials (created from the example file, gitignored)
  tests/                    unit (test_services.py, test_persistence.py, test_idempotency.py, test_math_logic.py)
                            + integration (test_main.py, via FastAPI's TestClient)
                            + performance (test_performance.py, benchmark assertions)
                            + e2e/ (Playwright + pytest, drives the real UI against live servers)
frontend/
  app.py                   Flask app serving the UI
  requirements.txt          Frontend dependencies
  templates/                HTML pages (Jinja2)
  static/js/                API client, page logic, formatting helpers
  static/css/                Styling
  tests/                    Frontend JS tests (Node's built-in test runner)
.github/workflows/         CI: runs backend + frontend tests on every push/PR
```

## Getting Started

### 1. Install dependencies

```powershell
python -m pip install -r backend\requirements.txt
python -m pip install -r frontend\requirements.txt
```

### 2. Configure the database

Copy `backend\.env.example` to `backend\.env` and fill in local MySQL credentials.

### 3. Create the database tables

```powershell
cd backend
python db_conn.py
```
This creates the `portfolio` table and seeds a `balance` table with a starting cash balance of $10,000.

### 4. Start the backend

```powershell
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

### 5. Start the frontend (in a second terminal)

```powershell
cd frontend
python app.py
```

The app is then available at `http://127.0.0.1:5000/portfolio`.

### 6. Explore the API directly

Interactive Swagger docs are available at `http://127.0.0.1:8000/docs`.

## Running Tests

Backend (unit, integration, and performance tests):
```powershell
cd backend
python -m unittest discover tests -v
```

Frontend:
```powershell
cd frontend
node --test
```

Both run automatically in CI (GitHub Actions) on every push and pull request.

### Running the E2E Tests

These drive a real browser against both live servers, so they need extra setup beyond `backend/requirements.txt`:

```powershell
cd backend
python -m pip install pytest pytest-playwright
python -m playwright install
```

Both servers need to be running first (see **Getting Started**, steps 4–5), then in a third terminal:

```powershell
cd backend\tests\e2e
python -m pytest -m e2e
```

To watch it run in a real, visible browser, slowed down:
```powershell
python -m pytest -m e2e --headed --slowmo 1000
```

⚠️ **This resets the database.** A `clean_database` fixture calls `DELETE /test/reset` before and after every e2e test, which clears the `portfolio` table and resets the cash balance to $10,000 - on whatever database the `.env` file points to. There's no separate test database configured, so the e2e suite shouldn't be run against data that needs to be kept.

## API Reference

| Method | Endpoint | Description |
|---|---|---|
| GET | `/portfolio` | List the raw buy/sell transaction history |
| POST | `/portfolio` | Buy a new holding (validates ticker, funds, etc.) |
| GET | `/portfolio/holdings` | One aggregated holding per ticker (net quantity, average cost) |
| POST | `/portfolio/sell` | Sell shares of an existing holding at the live market price |
| GET | `/portfolio/performance` | Holdings enriched with live prices + portfolio summary |
| GET | `/stocks/search?q=` | Search real tickers/companies (stocks, ETFs, bonds) |
| GET | `/stocks/price/{ticker}` | Look up a ticker's live price |
| GET | `/stocks/trending` | Currently most-active real tickers, for the Buy page's popular tickers widget |
| GET | `/balance` | Get current cash balance |
| POST | `/balance/deposit` | Add funds to the balance |
| POST | `/balance/withdraw` | Remove funds from the balance (can't go below $0) |
| DELETE | `/test/reset` | ⚠️ Test-only. Clears the `portfolio` table and resets the balance to $10,000. Used by the e2e test suite; not meant for normal use. |

### Idempotency

`POST /portfolio`, `POST /portfolio/sell`, `POST /balance/deposit`, and `POST /balance/withdraw` accept an optional `Idempotency-Key` header. If a client doesn't receive a response to one of these requests (e.g. a dropped connection) and retries with the **same** key, the original result is replayed instead of the operation running again - so a retried "buy 100 shares" never buys them twice. The frontend generates a fresh key automatically per request.
